`src/apps/example/` fits a polynomial to noisy samples of a known function by
minibatch gradient descent. It exists to show the repository's conventions in
code that runs in a second on a CPU.

| File | Contents |
|---|---|
| `config.py` | `ExampleTrainingConfig` and `ExampleExperimentConfig`, frozen dataclasses |
| `presets.py` | `EXAMPLE_PRESETS`, the named registry, derived from one base with `dataclasses.replace` and a loop |
| `trainer.py` | `train(config, output_root)`, the lifecycle, and `main()` |
| `__main__.py` | `python -m src.apps.example <preset> [overrides]` |

## Conventions it demonstrates

- **Immutable configuration.** The parsed configuration is a frozen dataclass.
  Derived values (the run directory, the resolved seed) live in a
  `RunContext`, and `config.json` records what executed.
- **Explicit schedules.** Every preset carries a complete
  `LearningRateSchedule`. `example-smoke` has a shorter horizon, so it builds
  its own schedule instead of inheriting the default's warmup.
- **Named random domains.** Training data, minibatch indices, initialization,
  and evaluation draw from separate named streams. The evaluation stream can
  be used any number of times without moving the training streams.
- **Pinned metrics.** PSNR is computed with an explicit peak taken from the
  reference function's known range, not from a run's maximum.
- **Presets as data.** Sweep arms are generated by a loop over learning-rate
  scales; no code branches on a preset name.

## Commands

```bash
python -m src.apps.example example-default
python -m src.apps.example example-smoke --training.iterations 50
python -m src.apps.example --help
```

Outputs land in
`outputs/example-default_<timestamp>_<pid>/` with `config.json`,
`provenance.json`, `metrics.json`, and `coefficients.json`.
